# Studexo Database Architecture (Phase 8B.3B)

Studexo uses PostgreSQL (planned on Supabase) with **Drizzle ORM (`0.45.4`)** and **`postgres.js` (`3.4.9`)**. The database foundation implements the reconciled MVP schema across **47 tables** (including **2 reference lookup tables**), **36 PostgreSQL enums**, **19 custom PostgreSQL functions**, **50 triggers** (`33` `updated_at` triggers + `17` domain/lifecycle triggers), and **126 indexes** (`122` in `0000` + `4` GIN trigram indexes in `0001`) via offline Drizzle migration artifacts (`drizzle/0000_init_studexo_mvp.sql`, `drizzle/0001_studexo_integrity_triggers_and_extensions.sql`, `drizzle/0002_studexo_user_insert_and_file_rollback_guards.sql`, and `drizzle/0003_studexo_schema_lockout_and_outbox_guard.sql`) without connecting to a live external database.

## 1. Schema Isolation (`studexo`)

All 47 Studexo domain tables, 36 PostgreSQL enums, 19 functions, and 50 triggers live inside the dedicated **`studexo`** PostgreSQL schema (`pgSchema('studexo')`).

- Never reference or modify Supabase-managed schemas (`auth`, `storage`, `realtime`) or `public` tables via foreign keys.
- External authentication identities are linked indirectly through `studexo.auth_identities(provider, provider_subject)` and nullable `studexo.users.supabase_auth_user_id`, cleaned up asynchronously after local purge via `studexo.external_identity_purge_outbox`, and guarded against pre-purge re-registration via `SECURITY DEFINER` `studexo.is_auth_user_pending_purge(uuid)` plus `studexo.guard_users_lifecycle()`.
- `0003_studexo_schema_lockout_and_outbox_guard.sql` explicitly revokes schema, table, sequence, function, and default-privilege access on `studexo` from `PUBLIC` and Supabase PostgREST roles (`anon`, `authenticated`, `service_role`) when present in `pg_roles`.
- Migration tracking uses a dedicated **`drizzle`** schema (`drizzle.__drizzle_migrations`) pre-created by the operations administrator with `AUTHORIZATION studexo_migrator`, completely separated from `studexo`, excluded from PostgREST Exposed Schemas, and locked down against `PUBLIC`, `anon`, `authenticated`, `service_role`, `studexo_app`, `studexo_purge_worker`, and `studexo_catalog_admin`.
- Private file object references live in `studexo.stored_files(storage_bucket, object_key)` with `CHECK (visibility = 'private')` rather than foreign keys into `storage.objects`.

## 2. Separated Role-Scoped Connection Architecture & Production TLS

| Purpose | Env Variable | Role / Pool Mode | Client Settings |
|---|---|---|---|
| Runtime API Queries | `DATABASE_URL` | `studexo_app` / Supavisor Transaction Pooler (`:6543`) | `prepare: false`, `max: DB_POOL_MAX` (`5`), `idle_timeout: DB_IDLE_TIMEOUT_SECONDS` (`20`), `connect_timeout: DB_CONNECT_TIMEOUT_SECONDS` (`10`) |
| Schema Migrations | `DIRECT_DATABASE_URL` | `studexo_migrator` / Direct or Session PostgreSQL (`:5432`) | Executed strictly via `bun run db:migrate` (`src/server/db/migrate.ts`, `prepare: false`, `max: 1`, `resolvePostgresTlsConfig` + optional `DB_SSL_ROOT_CERT`) targeting pre-provisioned `drizzle.__drizzle_migrations`; `drizzle-kit` offline `generate`/`check` use `drizzle.config.ts` (`schemaFilter: ['studexo']`, `migrations: { schema: 'drizzle', table: '__drizzle_migrations' }`) |
| Purge Worker | `WORKER_DATABASE_URL` | `studexo_purge_worker` / Isolated worker pool | `prepare: false`, `max: WORKER_DB_POOL_MAX` (`2`); parsed strictly via `parseWorkerEnv()` (fails closed if missing; never required or opened by the API process) |
| Catalog Admin *(deferred)* | `CATALOG_ADMIN_DATABASE_URL` | `studexo_catalog_admin` (`NOLOGIN`) | Kept `NOLOGIN` with zero staging credentials until curated catalog ingestion / administration runtime is implemented |

### Production TLS Enforcement

- In `NODE_ENV === 'production'`, `resolvePostgresTlsConfig()` strictly rejects insecure URL parameters (`sslmode=disable`, `allow`, `prefer`, `require`, `no-verify`, or `ssl=false`) because `postgres@3.4.9` maps `sslmode=require` to `rejectUnauthorized = false`.
- Production clients always enforce verified TLS (`'verify-full'` or `{ rejectUnauthorized: true, ca }` when `DB_SSL_ROOT_CERT` is configured), preserving both certificate chain and server hostname verification.
- Outside production, loopback/Unix-socket targets (`localhost`, `127.0.0.1`, `::1`) permit unencrypted local verification clusters unless `verify-full` / `verify-ca` is requested, while remote hosts still require verified TLS.

### Lazy Startup & Real Readiness Probing

- Importing `src/server/db/index.ts` or calling `createApp()` **never** opens a database socket.
- `GET /api/health` remains strictly database-independent (`200 OK`) and never opens `getDb()`.
- `GET /api/ready` calls bounded `checkDatabaseReadiness()` (`SELECT 1` with strict timeout), returning HTTP `200` (`status: 'ok'`, `database.connected: true`) only when configured and reachable, and HTTP `503` (`status: 'degraded'`, `database.connected: false`) when unconfigured, unreachable, or timed out—never exposing DB URLs, credentials, SQL errors, or stack traces.
- `closeAllDbs()` / `closeDb()` / `closeWorkerDb()` run cleanly on shutdown and no-op when uninitialized.

## 3. Complete Domain Inventory (47 Tables / 36 Enums)

- **Enums & Namespace (`enums.ts`):** `studexoSchema` + 36 domain enums (`score_status` with 7 values including `'not_tested' | 'not_applicable' | 'unknown' | 'waived'`; `notification_status` strictly 5 values `'queued' | 'sending' | 'sent' | 'failed' | 'cancelled'` with read tracking modeled solely via `read_at`; retired `grading_system`, `language_test`, `file_visibility`, `document_type`, and `ai_feature_key`).
- **Reference Lookup Tables (`reference.ts` — 2 tables):** `grading_scales`, `test_catalog` (with `has_numeric_score`).
- **Identity, Access & Consent (`identity.ts` — 4 tables):** `users` (with `supabase_auth_user_id`, `deletion_requested_at`, `deletion_scheduled_for`, `purge_state`, `purge_lease_owner`, `purge_lease_until`, `purge_attempts`, `last_purge_error`, `purged_at`; column-scoped `studexo_app` `INSERT` + `trg_users_lifecycle` `BEFORE INSERT OR UPDATE OR DELETE` enforcing `'student'`, `'active'`, `'none'` initial state and blocking re-registration while `is_auth_user_pending_purge(supabase_auth_user_id)` is true), `auth_identities`, `account_settings`, `user_consents` (append-only for `studexo_app` via `SELECT, INSERT` privilege grants; `studexo_migrator`, `studexo_purge_owner`, and `ON DELETE CASCADE` retain delete capability).
- **Student Profiles & Credentials (`profiles.ts` — 5 tables):** `student_profiles` (`birth_year` integer year `1000..9999`), `student_qualifications`, `student_test_scores` (replaces `student_language_scores`), `student_experiences`, `student_publications_and_projects`. All 4 credential tables include provenance fields (`verification_method`, `is_verified`, `verified_by_user_id`, `verified_by_role`, `verified_at`, composite `(evidence_document_version_id, user_id)` FK, `external_reference_url`, `verification_valid_until`) enforced by SQL `CHECK`s and `guard_student_credentials_verification()`.
- **Institutions (`institutions.ts` — 2 tables):** `institutions`, `institution_aliases` (plus required `pg_trgm` GIN trigram search indexes in `0001`).
- **Programmes (`programmes.ts` — 4 tables):** `programmes` (`UNIQUE (id, institution_id)`), `programme_intakes` (`UNIQUE (id, programme_id)`), `programme_fees`, `programme_requirements` (optional FKs to `grading_scales` and `test_catalog`).
- **Scholarships (`scholarships.ts` — 5 tables):** `scholarships`, `scholarship_intakes` (`UNIQUE (id, scholarship_id)`, `UNIQUE (scholarship_id, cycle_label)`), `scholarship_programmes` (M:N link), `scholarship_eligibility_rules`, `scholarship_funding_components`.
- **Provenance & Verification (`verification.ts` — 3 tables):** `sources`, `verification_claims` (`ON DELETE RESTRICT` to catalog entities, supersession chain `superseded_by_claim_id` + `superseded_at`, immutable superseded history except explicit `execute_account_purge` `verified_by_user_id -> NULL` anonymisation executed as `studexo_purge_owner`), `verification_evidence` (database trigger-enforced immutability via `trg_verification_evidence_immutable`).
- **Documents & Private Storage (`documents.ts` — 3 tables):** `stored_files` (`owner_user_id -> users.id ON DELETE RESTRICT`, `UNIQUE (id, owner_user_id)`, purge lease/state tracking, `deleted_by_user_id` attributed exclusively via `SECURITY DEFINER` `studexo.request_stored_file_deletion(uuid, uuid)` for active owner or admin users, rolled back atomically from untouched `pending_purge -> none` solely via `SECURITY DEFINER` `studexo.revert_stored_file_deletion_request(uuid, uuid)` for `studexo_purge_worker`, protected against direct app/worker mutation or stale `deleted_by_user_id` in `purge_state = 'none'`, and cleared explicitly inside `execute_account_purge`), `documents` (`UNIQUE (id, user_id)`), `document_versions` (composite `(stored_file_id, user_id) -> stored_files(id, owner_user_id) RESTRICT`, `(document_id, user_id) -> documents(id, user_id) CASCADE`, `FOR SHARE` lock on `stored_files` during insert).
- **Applications & Bookmarks (`applications.ts` — 7 tables):** `saved_opportunities` (`= 1` target XOR check), `university_applications` (`UNIQUE (id, user_id)`, composite programme/institution `RESTRICT` + composite intake `RESTRICT`), `scholarship_applications` (`UNIQUE (id, user_id)`, composite intake `RESTRICT` + composite university app `NO ACTION`), `application_documents` (canonical column `document_state`, per-application `pg_advisory_xact_lock` on `INSERT`/`UPDATE`/`DELETE`, submitted lock, `'replaced'`/`'withdrawn'` immutability, replacement cycle guard, active-doc partial uniques), `application_checklists`, `application_notes`, `application_status_history` (with `user_id NOT NULL` + composite app FKs; privilege-based `SELECT, INSERT` append-only enforcement for `studexo_app`, while `studexo_migrator`, `studexo_purge_owner`, and `ON DELETE CASCADE` retain delete capability).
- **Planner & Notifications (`planner.ts` — 4 tables):** `planner_tasks` (`UNIQUE (id, user_id)`), `planner_events` (`UNIQUE (id, user_id)`), `notification_preferences`, `notification_deliveries` (`UNIQUE (user_id, dedupe_key)`, `read_at` invariant `CHECK`, `<= 1` across 4 optional composite FKs).
- **AI Orchestration (`ai.ts` — 7 tables):** `ai_prompt_versions`, `ai_permissions`, `ai_conversations`, `ai_messages`, `ai_runs`, `ai_usage_records`, `ai_run_context_links` (`= 1` across 9 `ON DELETE CASCADE` targets).
- **External Identity Outbox (`outbox.ts` — 1 table):** `external_identity_purge_outbox` (intentionally zero FKs to `users` so records survive user deletion, with boolean `is_auth_user_pending_purge(uuid)` preventing pre-purge re-registration without opening outbox table privileges to `studexo_app`).

## 4. Ownership, Integrity & Concurrency Architecture

1. **Cross-User Isolation at Schema Level:** Owned references use composite foreign keys pairing the child ID with `user_id` (or `owner_user_id`) so cross-user references fail at the PostgreSQL constraint layer.
2. **Composite Optional FKs Without Partial Nullification Bugs:** Optional owned composite FKs (`NOT NULL user_id`) use `ON DELETE NO ACTION` paired with `7` `BEFORE DELETE` unlinker triggers that null only the optional referencing column while preserving `user_id`. Application intake references (`programme_intakes`, `scholarship_intakes`) enforce `ON DELETE RESTRICT` so in-use intakes cannot be silently unlinked into partial-unique index collisions.
3. **Storage-First Deletion & Two-Stage Account/File Purge (`src/server/modules/lifecycle/storageAndPurge.ts`):**
   - `stored_files.owner_user_id` enforces `ON DELETE RESTRICT`.
   - **Stage 1 (API — `studexo_app`):** `requestDraftStoredFileDeletion()` authenticates ownership, invokes `studexo.request_stored_file_deletion(fileId, actorUserId)` (`SECURITY DEFINER`, owned by `studexo_migrator`), locks the `stored_files` row `FOR UPDATE` (paired with `FOR SHARE` in `guard_document_versions_integrity()`), verifies active actor & ownership/admin authority and zero `document_versions` references, sets `deleted_by_user_id`, transitions `purge_state` `none -> pending_purge`, and returns an async queued `202` outcome without touching worker DB privileges or Storage APIs.
   - **Stage 2 (Background Worker — `studexo_purge_worker`):** `processPendingStoredFileDeletion()` discovers `pending_purge` / retryable files via `FilePurgeWorkerRepository`, re-checks `countBlockingReferences()` under `FOR UPDATE` lock, invokes `studexo.revert_stored_file_deletion_request(fileId, ownerUserId)` (`SECURITY DEFINER`, `EXECUTE` granted solely to `studexo_purge_worker`) if an untouched `pending_purge` file is blocked by newly added references (atomically clearing `deleted_by_user_id` and `purge_requested_at`), acquires a `purging` lease, deletes the Storage object, verifies object absence, and marks the row `purged`/`deleted` (`markFilePurged`) while preserving `deleted_by_user_id`. Concurrent upload completion races are blocked by `assertUploadCanComplete` + `trg_stored_files_lifecycle`, and expired `purging` leases recover back to `purge_failed` via `recoverExpiredStoredFilePurgeLease()`.
   - Direct `DELETE` on `studexo.users` and `studexo.stored_files` is blocked for all roles except inside `studexo.execute_account_purge(uuid)` owned by `studexo_purge_owner` (with `REVOKE ALL ... FROM PUBLIC` enforced directly in `0001`) when `CURRENT_USER = 'studexo_purge_owner'` and `SET LOCAL studexo.purge_mode = 'account_purge'` is active — and `execute_account_purge` enforces `READ COMMITTED` (`25000`), refuses to run until 100% of the user's `stored_files` are confirmed `purge_state = 'purged'`, inserts into `external_identity_purge_outbox`, and explicitly clears `verification_claims.verified_by_user_id = NULL` and `stored_files.deleted_by_user_id = NULL` as `studexo_purge_owner` before deleting dependent artifacts and `studexo.users`.
   - Interrupted account purges (`users.purge_state = 'purging'` with expired `users.purge_lease_until`) recover via `recoverInterruptedAccountPurge()`, which refuses to steal active user/file leases, recovers expired file leases, re-verifies Storage object absence directly against Storage (never assuming DB rollback restores deleted objects), inspects `external_identity_purge_outbox`, and transitions `users.purge_state` strictly to `'purge_failed'` while preserving `status = 'pending_deletion'`.
   - Supabase Storage adapters, concrete Drizzle repositories, and scheduled cron/worker execution remain documented architectural contracts for future live infrastructure integration.
4. **Verification Claim Supersession Concurrency (`src/server/modules/verification/supersession.ts`):**
   - Enforces `READ COMMITTED` isolation both in TypeScript (`{ isolationLevel: 'read committed' }`) and PL/pgSQL (`ERRCODE = '25000'` if non-`read committed`).
   - Acquires a deterministic MD5-derived 64-bit `pg_advisory_xact_lock` per `(target_type, target_id, field_path)` **before** reading mutable state, re-reads target and replacement claims under lock, rejects ineligible replacement statuses (`superseded`, `rejected`, `disputed`), walks `WITH RECURSIVE` to forbid any cycle (2-node or 3+ nodes), enforces conditional `UPDATE` + exact 1-row assertion, preserves superseded history (with explicit `execute_account_purge` `verified_by_user_id -> NULL` anonymisation restricted solely to `CURRENT_USER = 'studexo_purge_owner'` while the user is in `pending_deletion`/`purging`), and wraps operations in a bounded 3-attempt jittered retry helper for `40P01` / `40001`.

## 5. Offline Migration Order & Operations Handoff

1. `drizzle/0000_init_studexo_mvp.sql`: Pure Drizzle-generated DDL (`studexo` schema with idempotent + ownership-verified bootstrap guard, 36 enums, 47 tables, composite FKs, unique indexes, check constraints).
2. `drizzle/0001_studexo_integrity_triggers_and_extensions.sql`: Required `pg_trgm` extension verification + 4 GIN trigram indexes (raising SQLSTATE `0A000` if unavailable), initial 17 PostgreSQL functions, and 50 triggers (`33` `updated_at` + `17` domain/lifecycle).
3. `drizzle/0002_studexo_user_insert_and_file_rollback_guards.sql`: Forward Phase 8B.2L security & rollback hardening updating `guard_users_lifecycle()` + `trg_users_lifecycle` (`BEFORE INSERT OR UPDATE OR DELETE`), updating `guard_stored_files_lifecycle()` to forbid non-NULL `deleted_by_user_id` or purge metadata in `purge_state = 'none'`, and adding `SECURITY DEFINER` `studexo.revert_stored_file_deletion_request(uuid, uuid)` (18th custom PostgreSQL function).
4. `drizzle/0003_studexo_schema_lockout_and_outbox_guard.sql`: Forward Phase 8B.3B hardening adding `SECURITY DEFINER` `studexo.is_auth_user_pending_purge(uuid)` (19th custom PostgreSQL function), updating `guard_users_lifecycle()` to block re-registration/binding while an identity is pending deletion or has an unpurged outbox record, and revoking `PUBLIC` + Supabase PostgREST (`anon`, `authenticated`, `service_role`) privileges and default privileges across `studexo`.
5. See [`docs/DATABASE_ROLES.md`](./DATABASE_ROLES.md) for hosted Supabase non-superuser `postgres` membership handling, SCRAM-SHA-256 role bootstrap (`studexo_migrator`, `studexo_purge_owner`, `studexo_app`, `studexo_purge_worker`, and `NOLOGIN` `studexo_catalog_admin`), pre-creation & lockout of the `drizzle` tracking schema, column-level privilege hardening, function `EXECUTE` grants, ownership transfer of `execute_account_purge(uuid)` to `studexo_purge_owner`, PostgREST exposed-schema exclusion, and live PostgreSQL verification gates.
